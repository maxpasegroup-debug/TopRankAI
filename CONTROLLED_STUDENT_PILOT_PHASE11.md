## Incident, fix and recovery protocol

- Stop new enrollment/expansion for any suspected unauthorized data/answer disclosure,
  privilege escalation, corruption, lost saved answers or unsafe consent behavior.
  Escalate to the named on-call/privacy owner immediately through the approved process.
- Preserve sanitized evidence; contain affected access/invitations/providers through
  approved controls. Do not export student data or broadly delete/rewrite records.
- Classify severity and blast radius, reproduce against approved isolated fixtures,
  implement the narrow fix on the current branch while preserving existing user work,
  rerun affected tests and real acceptance, and approve a new artifact.
- Verify a lost acknowledgment/retry and actual network disconnect, not just a mocked
  success. Inspect grant/order provenance rather than creating a new intent blindly.
- Rehearse code rollback to the compatible previous artifact. Database forward changes
  are not automatically reversible; restore only into a new approved isolated target
  and verify before a separately approved cutover. Keep originals intact.
- Record actual backup age, restore duration, reconciliation, session handling and any
  data loss against approved RPO/RTO. A runbook or archive listing is not a rehearsal.
- Document closure/retest; do not hide incidents by excluding participants from metrics.
